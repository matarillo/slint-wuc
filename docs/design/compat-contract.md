# Compatibility Contract

What the fork keeps so that code generated by the **unmodified** Slint 1.19.0 compiler, the interpreter, and the C++ API can build against it.
Evidence: [symbol-inventory.md](symbol-inventory.md) (section numbers below refer to it).

Each upstream item falls into one of three classes:

- **Keep**: same path, name, signature, and layout.
- **Seam**: same path, name, and the signatures the generated code calls, with exactly one implementation behind it.
  These replace upstream's abstractions; nothing else implements them.
- **Drop**: removed, or kept as a stub that reports "unsupported".

## Keep

- Crate `i-slint-core` (`i_slint_core`) and the paths of everything listed in inventory §1.4, §1.8, and §2.
- `ItemTreeVTable` and its callers (`visit_item_tree*`, `register_item_tree`, `unregister_item_tree`, `ItemRc`, `ItemWeak`, `ItemTreeNode`), unchanged.
- Every native item struct the interpreter registers (§2.4): name, `#[repr(C)]`, field names and types matching `item!` in `builtin_elements.rs`, `FieldOffsets`, `SlintElement`, and the `slint_get_*VTable` statics.
  `Native*` items are the exception (see Drop).
- `CachedRenderingData`: `#[repr(C)]`, two `Cell<usize>` fields, in every item.
  C++ redefines it by hand (`api/cpp/cbindgen.rs:1003`).
  It moves to `visual_tree` and stays re-exported as `item_rendering::CachedRenderingData` and `partial_renderer::CachedRenderingData`.
- `properties`, `callbacks`, `model`, `layout`, `animations`, `timers`, `input`, `item_focus`, `menus`, `accessibility`, `translations`, `styled_text`, `data_transfer`, `date_time`, `debug_info`, `builtin_functions`, `string`, `sharedvector`, `slice`, `lengths`, `graphics::{color, brush, border_radius, path, image}`.
- `rtti` and `ffi` features.
  The interpreter needs `rtti` and `SlintElement`; the C++ API needs `ffi`.
- Public API (§5.1, §5.2) marked "kept": `Window` (minus the methods under Drop), `ComponentHandle`, `Weak`, models, `Timer`, `invoke_from_event_loop`, `quit_event_loop`, `run_event_loop*`, `spawn_local`, image and color types, `PlatformError`.

## Seams

| Seam | Used by | Fork's single implementation |
|---|---|---|
| `window::WindowAdapter` trait, `WindowAdapterRc` | generated code (`sp::Rc<dyn sp::WindowAdapter>`, `window()`, `renderer()`), interpreter | `host::Win32WindowAdapter` (an HWND with a composition target) and a detached test adapter |
| `window::WindowAdapterInternal` | core | same type; popups, cursor, IME, menus |
| `renderer::Renderer` / `RendererSealed`, reached through `WindowAdapter::renderer()` | generated code (`register_font_from_path`, `register_font_from_memory`, `register_bitmap_font`, `rust.rs:5160-5180`), items (`text_size`, `char_size`, `font_metrics`, `text_content_widths`, `text_line_height`, text-input hit testing), interpreter (`free_graphics_resources`, font registration) | one struct backed by DirectWrite and the window's node table |
| `ItemVTable` | core, interpreter (through `rtti`), C++ headers | same slots, except `render` becomes `update_visual` (see below) |
| `platform` module | `api::Window::dispatch_event*` (`WindowEvent`, `WindowEventDispatchResult`), `items/text.rs` (`Clipboard`), `api.rs`/`future.rs`/`context.rs` (`EventLoopProxy`, `SetPlatformError`) | keeps those types and `update_timers_and_animations` / `duration_until_next_timer_update` |
| `SlintContext` | generated code (§1.5), builtin functions | holds `Box<dyn Platform>`; `host::Platform` is the only production implementation (see the rules below) |
| `slint::private_unstable_api` | generated code | the fork's facade crate; `ensure_context` creates the fork's context, `native_widgets` is empty |

Rules for seams:

- `RendererSealed` keeps only the methods listed above, plus `set_window_adapter`, `window_adapter`, `scale_factor`, `resize`, `mark_dirty_region` (no-op), and `take_snapshot` (implemented with visual capture, S3).
  Drawing methods, `text_layout_cache`, and `set_rendering_notifier` go.
- `ItemVTable::render` (which takes `&mut ItemRendererRef`) is replaced by `update_visual`.
  No generated code calls `render`; the C++ headers are regenerated from the fork, so the slot change is invisible to generated C++.
- The `Platform` trait leaves the public API, but stays inside core as a seam (decided in Phase 1).
  `host::Platform` implements it: the animation clock (`animations.rs:241`), click and cursor-blink intervals (`input.rs:1406`, `window.rs:1562`), clipboard, `open_url` (`lib.rs:215`), and the event loop.
  The only other implementations are unit-test doubles, which need their own clock and event-loop proxy; replacing the trait with a concrete type would have meant rewriting those tests for no gain at the generated-code boundary.
  Host-only operations (frame ticks) don't go through the trait.
- Long-press was Android-only upstream and went with Stage 1 pruning; touch long-press comes back with `WM_POINTER` input in Phase 3.
- `PlatformError::SetPlatformError` stays as a variant so matches in user code still compile.

## Drop

- `item_rendering::ItemRenderer` and the `Render*` traits (they stay, uncalled, until Phase 4: the parley text code is written against them), `partial_renderer` (except the re-export above and a `DirtyRegion` alias for `mark_dirty_region`), `textlayout`, `font_collection`, the parley/fontique/swash font stack, `graphics::{wgpu_*, bitmapfont, boxshadowcache, rendering_metrics_collector}`, `unsafe_single_threaded`, no_std, wasm, and other operating systems.
- Public API: `slint::platform` except the types under Seams, the renderer modules, `BackendSelector`, `android`, `wgpu_*`, `winit_030`, `fontique_012`, `BorrowedOpenGLTexture*`.
- Stubs that keep source compatibility: `Window::set_rendering_notifier` returns `Err(SetRenderingNotifierError::Unsupported)`; `GraphicsAPI` and friends stay as types; `set_xdg_app_id` does nothing.
- `register_bitmap_font` returns an error: bitmap fonts are an MCU feature.
- `Native*` items (§3.4 lists 31 statics; the Qt style is the only user).
  The `native_widgets` glob in `private_unstable_api` stays, empty.

## Consequences to Carry Into Later Phases

- **Phase 1**: the `shared-parley` feature also gates NFC normalization of key text (`input.rs:732`, `window.rs:1378`).
  Keep it by calling `icu_normalizer` directly.
- **Phase 1**: 13 runtime builtin bodies in `internal/common/builtin_functions.rs` reach the window adapter, and `open_url` reaches `Platform::open_url`; they move to the concrete host.
- **Phase 2**: the facade crate replaces `i_slint_backend_selector::with_global_context` in `ensure_context`.
  Glob-resolution traps in `re_exports` (§7): `sp::Transform` and `sp::ApproxEq` need explicit imports, `sp::ItemRc` needs the `pub use` at `items.rs:33`, and `ItemTreeVTable_static!` needs `vtable` in the glob.
- **Phase 5**: SVG text needs fonts (`graphics/image/svg.rs:103-126`, today through parley); give resvg a system font database.
- **Phase 7**: cbindgen names `item_rendering.rs` and `../renderers/software/lib.rs` explicitly (`cbindgen.rs:920-934`); update the list.
- **Phase 7**: the interpreter's `Drop for Instance` (`instance.rs:262-310`) duplicates `unregister_item_tree` and calls `free_graphics_resources`; keep that method on the renderer seam.
