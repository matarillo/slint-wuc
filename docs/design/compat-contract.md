# Compatibility Contract

What the fork must not change, so that code generated by the **unmodified** Slint 1.19.0 compiler, the interpreter, and the C++ API build against it.
Nothing in the fork's own code shows these constraints: they come from what upstream's generators emit.
The survey behind them (Phase 0, grep over `reference/slint-1.19.0`) is in git history as `docs/design/symbol-inventory.md`.

Each upstream item falls into one of three classes:

- **Keep**: same path, name, signature, and layout.
- **Seam**: same path, name, and the signatures the generated code calls, with exactly one implementation behind it.
- **Drop**: removed, or kept as a stub that reports "unsupported".

## Why These Are Fixed

- Generated code names core items through `sp::` (`slint::private_unstable_api::re_exports`), a namespace built from globs.
  So `sp::Transform` and `sp::ApproxEq` depend on explicit imports that win over the globs, `sp::ItemRc` on the `pub use` in `items.rs`, and `ItemTreeVTable_static!` on `vtable` being nameable from the glob.
  Six kinds of names are built at compiler run time (item classes, builtin enums and structs, `*_erased` helpers, extra layout functions, builtin globals), so a grep for `sp::` misses them; `tests/probe` and the conformance test catch them instead.
- `ItemVTable` mentions the window adapter in ten of its twelve members, and its layout is fixed by the generated code, the interpreter and the C++ headers alike. The fork changes one slot only (`render` to `update_visual`), which no generated code calls; the C++ headers are generated from the fork.
- `CachedRenderingData` is an ABI type: two `Cell<usize>` fields in every item, redefined by hand in C++ (`api/cpp/cbindgen.rs`), never named by the generators. It holds the visual tree's node handle.
- Generated Rust reaches the renderer: it registers fonts through `window_adapter.renderer()`, and text items measure through it in `layout_info`. So `WindowAdapter::renderer()` stays, with the measuring methods.
- `register_item_tree` and `unregister_item_tree` are called by generated code and by the interpreter's `Drop for Instance`, which duplicates core logic and calls `free_graphics_resources`.
- The interpreter reaches the core only through public paths plus `rtti`, which makes `#[derive(SlintElement)]` and the literal spelling `Property<..>` / `Callback<..>` of item fields part of the contract.
- `platform.rs` holds types that kept code can't do without: the arguments of `Window::dispatch_event*`, `Clipboard`, `EventLoopProxy`, `SetPlatformError`.
- 13 of the 79 builtin function bodies (`internal/common/builtin_functions.rs`) call the window adapter, and `open_url` the platform: the runtime function list is partly a window contract.

## Keep

- Crate `i-slint-core` (`i_slint_core`), and the paths of everything the generators emit.
- `ItemTreeVTable` and its callers, unchanged.
- Every native item struct the interpreter registers: name, `#[repr(C)]`, field names and types matching `item!` in the compiler's `builtin_elements.rs`, `FieldOffsets`, `SlintElement`, and the `slint_get_*VTable` statics. `Native*` items are the exception (see Drop).
- `CachedRenderingData`, re-exported under its upstream paths (`item_rendering`, `partial_renderer`).
- `rtti` (the interpreter) and `ffi` (the C++ API).
- The public API that applications use: `Window` (minus the methods under Drop), `ComponentHandle`, `Weak`, models, `Timer`, the event loop functions, `spawn_local`, image and color types, `PlatformError`.

## Seams

| Seam | Used by | The fork's single implementation |
|---|---|---|
| `WindowAdapter`, `WindowAdapterInternal` | generated code, interpreter, core | `host::Win32WindowAdapter`, hosted or detached |
| `Renderer` / `RendererSealed` through `WindowAdapter::renderer()` | font registration, text measurement, `free_graphics_resources` | DirectWrite and the window's node table |
| `ItemVTable` | core, interpreter, C++ headers | `update_visual` in place of `render` |
| `Platform` trait, inside core | the animation clock, click and blink intervals, clipboard, `open_url`, the event loop | `host::Platform` |
| `slint::private_unstable_api` | generated code | the fork's facade; `native_widgets` is empty |

- Why `Platform` stays a trait, out of the public API (Phase 1): the unit tests substitute their own clock and event-loop proxy. Replacing it with a concrete type would have meant rewriting those tests for no gain at the generated-code boundary.
- Why `PlatformError::SetPlatformError` stays: matches in user code still compile.
- `RendererSealed` keeps only what the callers above need, plus `take_snapshot` (visual capture, S3); `mark_dirty_region` is a no-op.

## Drop

- Upstream's renderers, `partial_renderer` (except the re-exports), the drawing side of `item_rendering`, bitmap fonts, wgpu, no_std, wasm, and other operating systems.
- Public API: `slint::platform` beyond the seam's types, `BackendSelector`, `android`, `wgpu_*`, `winit_030`, `fontique_012`, `BorrowedOpenGLTexture*`.
- Stubs keep source compatibility: `set_rendering_notifier` returns `Unsupported`, `GraphicsAPI` stays as a type, `set_xdg_app_id` does nothing, `register_bitmap_font` returns an error (an MCU feature).
- `Native*` items: the Qt style is their only user.

## Side Effects Found While Pruning

- The default feature `shared-parley` also decided whether key text is NFC-normalized; the fork calls `icu_normalizer` directly to keep it.
- SVG text resolves fonts through the context's font context, so `graphics/image` isn't free of the text stack.
- cbindgen follows the `mod` tree from `lib.rs`, and `tools/cpp-headers`, like upstream's `api/cpp/cbindgen.rs`, names `item_rendering.rs` explicitly: removing that file breaks the C++ headers without a matching edit.
