# Phase 7 の後のおすすめ

目的は、このフォークがモダンな Windows アプリの基盤として有効だと示すことです。
材料は、`docs/plan.md` の「Phase 7 の後に持ち越したこと」と、文脈を持たないサブエージェントによるレビュー (2026-11-18) です。
確かめたものに【確認】、確かめていないものに【推測】と付けます。
技術的な決まりは `docs/design/` に、経緯はコミットに書きます。この文書には、進み具合と判断だけを置きます。

## 結論

評価する人の印象を左右するのは、持ち越しの機能よりも、使い始めて最初の 10 分で引っかかる所です。
上流と同じ API で済む入口 (HWND の取得、導入手順) を先に整え、次に、Windows 11 らしさが目に見える所 (Mica、タイトルバー) と、採用を見送る理由になりうる所 (マルチモニター DPI) に進みます。

## Windows 11 らしさの見直し

最初のショーケース案 (Mica、ダークモード、アクセント色、ネイティブメニュー、トレイ、IME) は、Win32 の機能が動くことは示せますが、上流との差は示せません。

- トレイ、アクセント色、タイトルバーのダーク化は、上流の winit でもできます【確認】。
- ネイティブのメニューバーは古い Win32 の見た目で、Mica も隠します。キーボード操作と UI Automation のために既定には残し、見せる絵には入れません。
- 普通の枠に Mica を敷くだけでは、タイトルバーの帯が空いたまま残ります。

足すもの (おすすめの順):

- **A. タイトルバーへの内容の統合と Snap Layouts (M、拡張が要る)**: WinUI 3 の `ExtendsContentIntoTitleBar` に当たるものです。クライアント領域をタイトルバーまで広げ、キャプションボタンは DWM に描かせます (`DwmExtendFrameIntoClientArea`、`WM_NCCALCSIZE`、`DwmDefWindowProc`)【推測】。Snap Layouts、ボタンのダーク化、Mica が OS の決まりのまま付きます。`no-frame` の自前の最大化ボタンには、今は Snap Layouts が出ません (`WM_NCHITTEST` が `HTMAXBUTTON` を返さない【確認、`host/frame.rs`】)。ドラッグできる領域と自分のボタンをホストに伝える手段が `.slint` にないので、拡張が要ります。
- **B. ポップアップの見た目**: ダークモードのネイティブのメニューは済み (2026-11-19)。Slint 描画のポップアップに Acrylic を敷く案は、Fluent の背景が不透明なので効く場面が限られ、A より後です。
- **C. Composition への差し込み (L、拡張が要る)**: WebView2、動画、D3D のスワップチェーンを Slint の Visual の間に混ぜます。上流のどのバックエンドにもできない、このフォークの名前 (WUC) が指す強みです。A の拡張の形が決まってからにします。
- **D. 数字 (S)**: 起動時間、メモリー、アイドル時の CPU を上流と比べます。`probe-perf` はフォークの内部を使うので、`tools/upstream-gallery` を外から起動して測ります。
- **E. 設定への追従 (低)**: テキストのサイズ、アニメーションのオフ、ハイコントラスト。窓口を作るなら拡張が要ります。

MSIX、トースト通知、ジャンプリスト、タスクバーの進み具合は、アプリが HWND で呼べば足ります。フォークに足すものはありません。

## フォーク独自の拡張の形

A と C で要るものです。名前は 2026-11-20 に決めました (「決めたこと」)。

- 上流の前例: `slint::winit_030` (feature `unstable-winit-030`)。`Window` への拡張トレイト (`WinitWindowAccessor`) で、マイナーリリースで変わりうることと、Slint が管理する状態は上書きされうることを明記しています。`slint::android`、`unstable-wgpu-*` も同じ形です。
- フォークでも同じ形にします: `unstable-` 付きの feature、`Window` への拡張トレイト、同じ注意書き。例: `slint::wuc` のトレイトに、タイトルバーの領域の指定、ウィンドウメッセージの横取り、Composition のルートへの差し込み。
- 制約: 拡張を使うコードは上流ではビルドできません (両方で動かすには `cfg` が要る)。`.slint` 側は拡張できません (コンパイラーは上流のまま)。C++ などには、言語ごとの窓口が要ります。

## 決めたこと

- 独自の API (2026-11-19): 当面は HWND とサンプルにとどめる。Windows 11 らしさを見せるのに要るなら、拡張を作る。
- 配布 (2026-11-19): git の依存と patch の両方を README に書いて公開する。リポジトリは `matarillo/slint-wuc`。crates.io に別名で出すかは積み残し。
- ライセンス (2026-11-19): フォークの変更は Copyright © Kentaro Inomata、MIT-0。全体は GPLv3 で配る。`docs/design/license.md`。
- 最低 OS (2026-11-19): 22621 (22H2)。Mica の公開 API がここからで、22000 向けの代わりの動作を持たずに済む。
- マルチモニターの検証 (2026-11-19): 仮想ディスプレイドライバーは入れず、オーナーが実機で確かめる。
- `no-frame` の DWM の枠線と角丸 (2026-11-19): 上流と同じ見え方なので外さない。
- Slint 描画のメニューバーへの切り替え (2026-11-19): 当面は環境変数 `SLINT_NO_MUDA` のまま。
- ポップアップのフォーカス (2026-11-20): 一覧の根に落ちたフォーカスは、選ばれたリストの項目に渡す。ナレーターが、ポップアップの窓から来た選択のイベントを読まないため。
- 外からのドロップの提案 (2026-11-20): 修飾キーなしはコピー。上流の Qt と同じで、エクスプローラーに移動を返すとファイルが消されるため。
- 拡張の名前 (2026-11-20): feature `unstable-wuc`、モジュール `slint::wuc`、`Window` への拡張トレイト `WucWindowExt` (上流の `WinitWindowAccessor` は winit の窓を取り出すものなので、機能を足すこのトレイトには合わせない)。`wuc` は winit と同じく、バックエンドの固有名として扱う。上流の `unstable-winit-030` などの数字は、API に型が出る外部クレートの版なので付けない。A の API には `windows` クレートの型を出さない (版の結合を避ける)。C で Composition の型を出すときに、版を名前に入れるかを決め直す。`slint::windows` は、アプリの `windows` クレートの名前を隠すので選ばなかった。
- A の形 (2026-11-20): unstable な API なので、新しい発見があれば破壊的変更もありうる前提で決めた。ドラッグできる領域は上流の `WindowMoveArea` で表し、ホストは上流と同じく、押して動かしたときに移動を始める。タイトルバーまで広げた窓でだけ、ダブルクリックで最大化と復元を切り替え、右クリックでシステムメニューを出す。`WM_NCHITTEST` で `HTCAPTION` を返す案は、押せる要素かどうかの推測を誤るとボタンが押せなくなるので選ばなかった。キャプションボタンは DWM が描き、Slint の描画はその上に重なる。そこでホストが Window の背景からボタンの矩形を抜き、背景が単色ならキャプションの色をそれに揃える。アプリに任せる案は、どのアプリにも同じコードが要るので選ばなかった。自前でボタンを描く案は spike が要り、DWM の見た目を真似し続けることになるので見送った。
- 公開 (2026-11-20): `matarillo/slint-wuc` を公開で作り、push した。最初のタグは `v1.19.0-wuc.1` で、README はこのタグを指す。上流の examples 3 つが、GitHub のタグから git の依存と patch の両方でビルドできた (`tools/upstream-examples.ps1 -Git v1.19.0-wuc.1`)。

## 積み残し

- 配布の長期の形: 別名 (`slint-wuc`) で crates.io に公開するか。公開するなら、`slint`、`i-slint-core`、`i-slint-common`、`i-slint-core-macros` の改名とメタデータの直しが要る。
- SixtyFPS (info@slint.dev) に確かめること: 第三者が配る改造版を Royalty-free 2.0 で使えるか (使えると読んでいる)、有償の Software License 3.0 がフォークに及ぶか、「slint-wuc」の商標上の扱い。確かめるまでは、`LICENSE.md` と README に「私たちの解釈」「不明」と書いておく。
- Mica と、全機能のメニューバーの併用 (L)。ホストがコンポジションでメニューバーを描き、ドロップダウンを `TrackPopupMenuEx` で出す案。

## 次の候補

1. A: 実装した (2026-11-20、`slint::wuc`、`examples/titlebar`、`docs/design/windows.md` の Title Bar)。オーナーが手で確認した (ドラッグ、ダブルクリック、右クリック、Snap Layouts、別の DPI、ダークモード)。ネイティブのメニューバーを持つ窓は広げられない (`SLINT_NO_MUDA` が要る)。

## 確かめていないこと

- `no-frame` の窓で、`WS_CAPTION` がないことによる、スナップや最小化のアニメーションの違い
- `no-frame` と MenuBar の併用 (上流もしていない)
- リダイレクション面を残したまま `DwmEnableBlurBehindWindow` と黒の背景ブラシを使っても透けなかった理由
- `AboutSlint` ウィジェットが正しく描けるか。Royalty-free 2.0 で使うアプリは、`AboutSlint` かバッジで Slint を使っていることを示す必要がある
- crates.io に上流の 1.20 が出たあとも、`slint = "1.19"` に対して patch の 1.19.0 が選ばれるか
- `REUSE.toml` とヘッダーが REUSE の仕様を満たすか (`reuse lint` は回していない)
- ポップアップのフォーカスを、NVDA と JAWS が読むか
- 管理者権限で動くアプリが、エクスプローラーからのドロップを受けないこと (UIPI による【推測】)
