# 作業の順番

今の作業の順番と条件を置く、ただ 1 つの一覧です。フォークを使う相手は、当面オーナー自身です。2026-11-21 から凍結しています ([凍結](#凍結))。
節目ごとにファイルを増やさず、この文書を書き換えます。終わった項目は消し、経緯はコミットに、決まりは `docs/design/` に書きます。1 万字を超えたら削ります。
確かめたものに【確認】、確かめていないものに【推測】と付けます。これまでの記録は `docs/plan.md` (Phase 0〜7) と `docs/recommendations-after-phase7.md` (2026-11-18〜20) にあります。

## 主張と費用

- 上流の `.slint` と Rust のコードが、手を入れずに動く。上流のテストケース、gallery、Rust の example と demo (23 個。残りは外した API か上流の不備)、実際のアプリ 1 つ (slokk-slint の写し。`Cargo.toml` の 2 行で動く) で確かめた【確認、`docs/design/upstream-examples.md`、`docs/design/app-compat.md`】。
- 上流の winit にまだない Windows の統合がある (窓の外に出るポップアップ、ダークなメニュー、ドロップの受け側、タイトルバーへの統合)【確認、`docs/design/windows.md`】。どれも上流の winit への変更でも実現でき、言えるのは「今使える」まで。
- フォークでなければならない理由は、UI が Composition のビジュアルツリーであること。アプリのスワップチェーンと WebView2 を `Image` に置け、Slint の要素と重なり、内容が変わっても同期パスは走らない (4)。WebView2 への入力の転送は、上流の API と HWND だけでアプリが組めた (6)。できないのはアクセシビリティ、ドロップ、ペンの筆圧【確認、`docs/design/embedding.md`】。wgpu 連携を外したフォークは、wgpu で描くアプリには上流に劣る。
- 費用: 速くも軽くもない (`docs/design/costs.md`)。実際のアプリでは gallery より重く、窓が上流より 60 ms 遅れて出て、private メモリは 128 MB、毎フレーム `Path` を作り直すアニメーションの CPU は上流の 2.3 倍【確認、`docs/design/app-compat.md`】。Rust だけ、Windows 11 22H2 以降、`=1.19.0` に固定、保守する人は 1 人。

## 凍結

2026-11-21 に、機能を足すのを止めました (Fable の判断をオーナーが採った)。実験の答えは出ています: 上流のコードは手を入れずに動き、速くも軽くもならず、フォークでなければならないのは差し込みだけ。その差し込みを含め、フォークにしかない機能を使うアプリがありません (slokk-slint の本体は上流の 1.18 のまま【確認】)。使うアプリがないまま決めた API は、あとで要る形と合わなくなりやすく、開発を続けるフォークには上流の新しいバージョンごとに費用がかかります。

再開するのは、次のどれか 1 つが起きたときです。

- Slint の要素の上や下に WebView2、動画、D3D の内容を置くアプリが決まった (順番の 9 から始める)。
- 作ること、確かめること自体を目的に再開する (8 から始める)。
- 1.20 が出た (10 を 1 回だけ行う)。
- 上流の winit に、窓の外に出るポップアップやドロップの受け側が入った: 残る理由が差し込みだけになり、続けるかを決め直す。
- 外の誰かが使いたいと言ってきた (13 を始める)。

## やらないもの

| 項目 | 理由 | 見直す条件 |
|---|---|---|
| 倍率の違うモニターの間の移動 (slokk-slint と `probe-embed`) | 別の機械を用意する手間に見合わない (2026-11-21)。同じ機械の 125 % と `SLINT_SCALE_FACTOR=2` では配置が合う【確認】 | 別のモニターの環境を使うとき |
| ドラッグの送り側 (`start_drag`)、画像 (`CF_DIB`)、`CFSTR_PERFORMEDDROPEFFECT` | 上流の winit にもない。slokk-slint は `DragArea` も `DropArea` も使わない【確認】 | アプリが要るとき |
| スライドとリサイズの残りの引っかかり (M) | 1 コマ 12〜15 ms のうち 5〜7 ms が、UI Automation のクライアントがいるときのアクセシビリティの更新。上流の分は測れていない。間引きはかえって悪かった【確認、`docs/design/app-compat.md`】 | 11 を始めるとき。先に上流の 1 コマを測る方法を作る |
| アニメーションの Composition への委譲 (L) | 引っかかるのは幅のアニメーションで、レイアウトの組み直しが要り、委譲しても引っかかりは縮まない【推測】 | 位置や不透明度のアニメーションで、フォークが上流より引っかかったとき (`docs/design/costs.md` の Why Not) |
| Mica と全機能のネイティブのメニューバーの併用 (L)、`SLINT_NO_MUDA` の API 化 | HMENU は必須でない (2026-11-19)。slokk-slint に `MenuBar` がない【確認】 | Alt/F10 と UI Automation の役割が要るアプリが出たとき |
| 設定への追従 (テキストのサイズ、アニメーションのオフ、ハイコントラスト) | 上流もしていない。スタイルは上流のコンパイラーの側にある | 相手に企業を含めるとき |
| Slint 描画のポップアップへの Acrylic | Fluent の背景が不透明で、効果が見える場面が少ない | ほかのスパイクのついでに安く作れたとき |
| 言語バインディング、crates.io への別名公開 | 大きさ L の作業が続き、利用者がいない。商標の扱いを確かめていない | 外の利用者が求めたとき |
| 16384 px を超えるテキスト、コミット前に壊したテキストのアトラス、カスタムカーソル | 今のアプリで起きない | エディター型のアプリを作るとき |

## 確かめていないこと

- slokk-slint でフォークが重い理由: private メモリ 128 MB (gallery は 47 MB)、起動の 60 ms の遅れ、スプラッシュの CPU。判断に要るときに内訳を測る (11)。
- 1.20 が crates.io に出たあとも、`slint = "1.19"` に対して patch の 1.19.0 が選ばれるか。
- 仮想化しない長いリストで毎フレームテキストが変わるときに、アトラスのページが残るか (`docs/design/visual-tree.md`)。
- `no-frame` の窓で、`WS_CAPTION` がないことによる、スナップや最小化のアニメーションの違い。
- ポップアップのフォーカスを NVDA が読むか。
