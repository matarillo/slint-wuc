# 作業の順番

今の作業の順番と条件を置く、ただ 1 つの一覧です。相手は、当面オーナー自身です。
節目ごとにファイルを増やさず、この文書を書き換えます。終わった項目は消し、経緯はコミットに、決まりは `docs/design/` に書きます。1 万字を超えたら削ります。
確かめたものに【確認】、確かめていないものに【推測】と付けます。これまでの記録は `docs/plan.md` (Phase 0〜7) と `docs/recommendations-after-phase7.md` (2026-11-18〜20) にあります。

## 主張と費用

- 上流の `.slint` と Rust のコードが、手を入れずに動く。上流のテストケース、gallery、プローブと、実際のアプリ 1 つ (slokk-slint。`Cargo.toml` の 2 行で動き、画面はレイアウトが同じ) で確かめた【確認、`docs/design/app-compat.md`】。
- 上流の winit にまだない Windows の統合 (窓の外に出るポップアップ、ダークなメニュー、ドロップの受け側、タイトルバーへの統合)【確認、`docs/design/windows.md`】。どれも上流の winit への変更でも実現でき、言えるのは「今使える」まで。
- フォークでなければならない理由は、UI が Composition のビジュアルツリーであることだけで、まだ実証していない。上流にも動画、Web、3D を `Image` で混ぜる例があり (`examples/ffmpeg`、`servo`)【確認】、wgpu 連携を外したフォークはその点で後ろにいる。
- 費用: 速くも軽くもない (`docs/design/costs.md`)。実際のアプリでは gallery より重く、窓が上流より 60 ms 遅れて出て、private メモリは 128 MB、毎フレーム `Path` を作り直すアニメーションの CPU は上流の 2.3 倍【確認、`docs/design/app-compat.md`】。Rust だけ、Windows 11 22H2 以降、`=1.19.0` に固定、保守する人は 1 人。

## 確かめていないこと

- slokk-slint でフォークが重い理由: private メモリ 128 MB (gallery は 47 MB)、起動の 60 ms の遅れ、スプラッシュの CPU。判断に要るときに内訳を測る。

- 1.20 が crates.io に出たあとも、`slint = "1.19"` に対して patch の 1.19.0 が選ばれるか。
- `AboutSlint` が正しく描けるか (Royalty-free 2.0 で使う条件)。3 で gallery の About のページを見る。
- 仮想化しない長いリストで毎フレームテキストが変わるときに、アトラスのページが残るか (`docs/design/visual-tree.md`)。
- `no-frame` の窓で、`WS_CAPTION` がないことによる、スナップや最小化のアニメーションの違い。
- ポップアップのフォーカスを NVDA が読むか。
- 追わないもの (判断を左右しない): JAWS、`no-frame` と MenuBar の併用、`DwmEnableBlurBehindWindow` が透けなかった理由、管理者権限のアプリへのドロップ。
